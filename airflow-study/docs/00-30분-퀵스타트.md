# 00. 30분 퀵스타트 (가장 빠른 체험)

이 문서는 **Airflow를 처음 보는 사람이 30분 안에 "돌아가는 것"을 직접 보고 만지는** 가이드입니다.
설명은 최소한으로, 명령어는 그대로 따라 칠 수 있게 적었습니다. 깊이 있는 설명은 [01번 문서](01-airflow-소개.md)부터 차근차근 이어 보세요.

## 학습 시간 배분

| 단계 | 시간 | 내용 |
|------|------|------|
| 1. 환경 띄우기 | 5분 | Docker로 Airflow 기동 |
| 2. UI 둘러보기 | 5분 | DAG 목록 / 상세 화면 |
| 3. DAG 1개 실행해보기 | 5분 | ▶ 버튼 → 녹색 셀 |
| 4. 로그 / Rendered Template 보기 | 5분 | `{{ ds }}`가 실제 값으로 치환된 것 확인 |
| 5. conf 주고 분기 실행 | 5분 | `{"mode": "premium"}` 전달해보기 |
| 6. 백필 1회 체험 | 5분 | 5일치를 한 번에 채워보기 |

## 사전 준비

- Docker Desktop 설치 + 메모리 4GB+ 할당
- 본 저장소를 clone하고 디렉토리로 이동
  ```bash
  cd airflow-study
  ```

## 1단계 (5분) — 환경 띄우기

```bash
# .env 준비 (한 줄로 끝)
cp .env.example .env

# DB 초기화 (최초 1회만)
docker compose up airflow-init

# 백그라운드 기동
docker compose up -d

# 상태 확인 — 모두 healthy가 될 때까지 30~60초 대기
docker compose ps
```

브라우저에서 http://localhost:8080 → 로그인 (`airflow` / `airflow`).

> 막히면? → [21. 트러블슈팅 FAQ](21-트러블슈팅-FAQ.md) → "Q. 컨테이너가 unhealthy"

## 2단계 (5분) — UI 둘러보기

로그인 직후 보이는 DAG 목록:

| 보이는 것 | 무슨 의미? |
|----------|----------|
| 좌측 토글 (회색) | DAG 비활성 — 자동 실행 안 함 |
| `dag_id` 컬럼 | DAG 이름 |
| `schedule` 컬럼 | 실행 주기 (`@daily`, `None` 등) |
| 우측 ▶ 버튼 | 수동 실행 |

`01_hello_airflow` 클릭 → 상세 페이지 진입 → 상단 탭들 (Grid / Graph / Code / ...) 한 번씩 클릭해 둘러보기.

> 더 보기 → [06. Web UI 개요](06-WebUI-개요.md)

## 3단계 (5분) — 첫 실행

`01_hello_airflow` 상세 페이지에서:

1. 좌측 상단 토글을 **ON**으로
2. 우측 상단 ▶ → **Trigger DAG**
3. Grid View에 새 컬럼이 생기고 **회색 → 라이트 그린 → 다크 그린** 순으로 변함
4. 모두 다크 그린(success)이면 끝

```
Grid View
                    start  hello  end
manual__...         ✓     ✓      ✓
```

> 안 됐다면? → [21. FAQ](21-트러블슈팅-FAQ.md) → "Q. ▶ 눌렀는데 안 도는 경우"

## 4단계 (5분) — 로그와 Rendered Template

성공한 `say_hello` 셀(녹색 박스) 클릭 → 우측 패널에서:

- **Logs** 탭: `Hello, Airflow!` 출력 확인
- **Rendered Template** 탭: 이 Task의 템플릿이 실제 어떤 값으로 치환됐는지 확인

이번엔 `02_template_variables` DAG로 가서 같은 절차로 트리거 → `print_via_bash` 로그를 보면:

```
ds                       = 2026-05-09
ds_nodash                = 20260509
ts                       = 2026-05-09T...
data_interval_start      = ...
data_interval_end        = ...
어제 날짜               = 2026-05-08
```

→ Airflow가 자동으로 채워주는 **모든 예약어**를 한 번에 볼 수 있음.

> 더 보기 → [15. 예약어 전체 레퍼런스](15-예약어-전체레퍼런스.md)

## 5단계 (5분) — conf로 분기 실행

`03_branching_example` 진입 → 토글 ON → ▶ → **Trigger DAG w/ config** →
Configuration JSON에 다음 입력:

```json
{"mode": "premium"}
```

→ Trigger.

Grid View에서 `process_premium`만 녹색이 되고 `process_basic`은 **회색(skipped)**이 되는 것 확인.

다시 한 번 ▶ → conf를 `{"mode": "basic"}`으로 → 반대 결과가 나옴.

> 더 보기 → [10. 단일실행 / Trigger](10-단일실행-Trigger.md)

## 6단계 (5분) — 백필 체험

CLI 한 줄로 5일치 DAGRun을 한꺼번에 만들어 봅니다.

```bash
docker compose exec airflow-scheduler \
  airflow dags backfill \
  --start-date 2026-04-01 \
  --end-date   2026-04-05 \
  04_backfill_demo
```

Web UI → `04_backfill_demo` 상세 → Grid View →
**5개 컬럼 (4/1, 4/2, ..., 4/5)** 이 한꺼번에 만들어지고 순차 실행되는 것 확인.

각 컬럼의 `show_interval` Task 로그를 열어보면 `ds`가 4/1, 4/2, ... 로 다름.

> 더 보기 → [11. 백필 (Web UI)](11-백필-WebUI.md), [12. 백필 (CLI)](12-백필-CLI.md)
