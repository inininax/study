# 19. 용어집 (Glossary)

Airflow를 처음 보면 비슷해 보이지만 다른 용어가 많습니다. 헷갈릴 때 이 페이지를 펼쳐 보세요.
가나다 / 알파벳 순으로 정리했습니다.

## 한국어 / 한자어

### 백필 (Backfill)
과거 시점의 DAGRun을 **여러 개 한꺼번에** 만들어서 채우는 작업.
Web UI ⟳ Backfill 또는 CLI `airflow dags backfill` 사용. → [11번 문서](11-백필-WebUI.md)

### 브랜칭 / 분기 (Branching)
조건에 따라 다른 Task로 갈리는 흐름. `BranchPythonOperator`나 `@task.branch` 사용.
선택되지 않은 가지의 Task는 **skipped** 상태.

### 의존성 (Dependency)
Task 간 실행 순서. `a >> b`이면 a 끝나야 b 시작. 그래프의 화살표.

### 재시도 (Retry)
실패한 Task를 자동으로 다시 시도. `retries=2`, `retry_delay=timedelta(minutes=5)` 등으로 제어.

### 캐치업 (Catchup)
DAG가 처음 ON될 때 `start_date`부터 현재까지의 모든 schedule 시점에 대해 자동으로 DAGRun을 만드는 동작. → [13번 문서](13-Catchup과-Schedule.md)

### 토글 (Toggle / Pause)
DAG의 활성/비활성 스위치. OFF면 자동 스케줄링 안 함. UI 좌측 동그라미.

### 파싱 (Parse)
Scheduler가 `dags/` 폴더의 `.py` 파일을 읽어 DAG 구조를 메타DB에 반영하는 과정.
보통 30초~5분 주기.

---

## A

### Asset
**Dataset의 새 이름** (Airflow 3.0+에서 도입 예정). 의미는 동일.

---

## B

### BashOperator
Shell 명령어를 실행하는 Operator. 가장 단순.
`bash_command`가 Jinja 템플릿됨.

### BranchPythonOperator
Python 함수의 반환값(다음 task_id 문자열)으로 분기. 선택되지 않은 다른 가지는 skipped.

---

## C

### Catchup
→ "캐치업" 항목 참고.

### Connection
외부 시스템 접속 정보 (DB host/user/pw 등). UI Admin → Connections.
`conn_id`로 DAG에서 참조. → [17번 문서](17-Variables-Connections-XCom.md)

### CeleryExecutor
Celery + Redis/RabbitMQ로 분산 실행하는 Executor. 중대형 환경용.

### Cron
시간 기반 스케줄 표현. `0 3 * * *` (매일 3시) 같은 형태.

---

## D

### DAG (Directed Acyclic Graph)
워크플로우 정의 자체. 방향이 있고 순환이 없는 그래프. Python 파일 1개에 보통 1개.

### DAGRun
DAG의 **1회 실행**. 같은 DAG라도 매일 실행하면 매일 새 DAGRun.
`run_id`, `logical_date`, `state`를 가짐.

### dag_id
DAG의 고유 ID. UI에 표시되고 CLI에서 참조 키. **한 번 정하면 바꾸기 어려움**.

### dag_run.conf
수동 트리거 시 함께 넘긴 JSON. DAG 안에서 `context["dag_run"].conf` 또는 `{{ dag_run.conf }}`로 접근.

### data_interval_start / data_interval_end
DAGRun이 처리할 **데이터 구간**. start는 포함, end는 미포함(exclusive).
`@daily`이면 24시간 구간. → [09번 문서](09-DAG-실행메커니즘.md)

### Dataset
2.4+의 data-aware 스케줄링 단위. URL 형태의 식별자. 하나의 DAG가 Dataset을 "갱신"하면, 그것을 구독하는 다른 DAG가 자동 트리거됨.

### depends_on_past
Task의 옵션. `True`면 같은 Task의 직전 logical_date가 success여야만 실행.

### ds
`{{ ds }}` — logical_date의 날짜 문자열 (`YYYY-MM-DD`). **가장 많이 쓰는 예약어**.

### ds_nodash
`{{ ds_nodash }}` — `ds`에서 `-` 제거 (`YYYYMMDD`).

---

## E

### EmptyOperator
아무것도 안 하는 Operator (구 `DummyOperator`). 그래프의 시작/끝 표식이나 join 노드로 사용.

### execution_date
**Deprecated**. 현대 Airflow에서는 `logical_date`를 사용. 의미는 동일.

### Executor
Scheduler가 결정한 Task를 실제로 어디서/어떻게 돌릴지 결정하는 컴포넌트.
Local / Celery / Kubernetes 등.

---

## F

### Fernet Key
Variable / Connection을 메타DB에 암호화 저장할 때 사용하는 키.
운영에서는 반드시 설정 (`AIRFLOW__CORE__FERNET_KEY`).

---

## G

### Grid View
DAG 상세 화면의 메인 뷰. **시간(logical_date) × Task** 격자. 가장 많이 봄.

### Gantt
한 DAGRun 내 Task의 시작/종료 시각을 간트차트로 표시. 병렬도 / 병목 파악.

---

## J

### Jinja Template
Operator 인자에 `{{ ... }}` 표현식을 쓰면 Task 실행 시점에 값으로 치환되는 템플릿 엔진. → [14번 문서](14-Jinja-Template.md)

---

## K

### KubernetesExecutor
Task 1개당 K8s Pod 1개를 띄워 실행하는 Executor. 격리·확장성 좋음.

### KubernetesPodOperator
임의 Pod을 띄워 실행하는 Operator. Executor와 별개.

---

## L

### LocalExecutor
같은 머신에서 multiprocessing으로 Task를 돌리는 Executor.
**본 학습 환경의 Executor.**

### Logical Date
DAGRun이 "논리적으로 표상하는 시각". 현대 Airflow에서 `data_interval_start`와 같음.
**물리적 실행 시각과 다름** (보통 logical_date + 한 schedule 간격 후에 실제 실행 시작).

---

## M

### Macros
Jinja 안에서 호출 가능한 함수/모듈 묶음. `{{ macros.ds_add(ds, -1) }}` 등.

### max_active_runs
DAG의 동시 실행 DAGRun 수 상한.

### max_active_tasks
DAG 안에서 동시에 running일 수 있는 Task 수 상한.

### Metadata DB
Airflow가 모든 상태(DAG, DAGRun, TaskInstance, Variable, Connection, ...)를 저장하는 DB.
PostgreSQL / MySQL / SQLite.

---

## O

### Operator
Task의 "종류"를 정의하는 클래스. 이를 인스턴스화하면 Task가 됨.
`BashOperator`, `PythonOperator`, `PostgresOperator` 등.

---

## P

### params
DAG/Task 정의 시 정적으로 넘기는 값. `{{ params.region }}`로 접근.
`Param` 클래스를 쓰면 Trigger UI에 폼 자동 생성.

### Pool
여러 Task가 공유하는 슬롯 풀. 외부 자원 (DB 연결 수 등)을 보호할 때 사용.
Admin → Pools.

### Provider Package
공식 또는 서드파티 통합 패키지. `apache-airflow-providers-postgres` 등.
Operator / Sensor / Connection Type을 묶어 배포.

### priority_weight
Task의 우선순위. 같은 Pool 안에서 큐잉 순서 결정.

### PythonOperator
Python 함수를 실행하는 Operator. `python_callable=함수`.

---

## R

### Rendered Template
Jinja가 실제 어떤 값으로 치환됐는지 보여주는 UI 탭. **디버깅 핵심**.

### retries / retry_delay
Task 실패 시 재시도 횟수와 간격.

### run_id
DAGRun의 고유 ID. 트리거 방식별 패턴이 다름:
- `scheduled__2026-01-03T00:00:00+00:00`
- `manual__2026-01-03T12:34:56...`
- `backfill__2026-01-03T00:00:00+00:00`
- `dataset_triggered__...`

---

## S

### Scheduler
DAG 파싱 + 스케줄링 + Task 큐잉 담당하는 Airflow 핵심 컴포넌트.
**죽으면 자동 실행 안 됨.**

### schedule
DAG의 실행 주기. cron, preset (`@daily`), `timedelta`, `Dataset` 객체, `None`.

### SequentialExecutor
한 번에 1개씩 순차 실행. SQLite 메타DB와만 호환. 학습 데모용.

### Sensor
특정 조건이 충족될 때까지 대기하는 특수 Operator. `FileSensor`, `S3KeySensor` 등.
`mode="poke"` (점유) vs `mode="reschedule"` (슬롯 양보).

### SLA (Service Level Agreement)
Task의 기대 완료 시간. 초과 시 SLA Miss로 기록 + 알림.

### start_date
DAG가 시작될 수 있는 가장 빠른 시각. **고정된 datetime이어야 함** (`datetime.now()` 금지).

### state
TaskInstance / DAGRun의 상태. `none/scheduled/queued/running/success/failed/up_for_retry/skipped/upstream_failed/up_for_reschedule` 등.

### SubDagOperator
다른 DAG를 Task처럼 임베드. **Deprecated** — TaskGroup 사용 권장.

---

## T

### Task
DAG 안의 작업 단위 한 개. `BashOperator(task_id=...)` 같은 인스턴스.

### task_id
Task의 DAG 내 고유 ID.

### TaskFlow API
2.0+의 `@task` 데코레이터 기반 DAG 작성 방식. 함수 반환값이 자동으로 XCom에.

### TaskGroup
Task들을 시각적으로 묶는 그룹. SubDag보다 가볍고 권장.

### TaskInstance (TI)
**Task의 1회 실행**. DAGRun이 만들어지면 각 Task마다 TI가 생김.
TI에 state / logs / try_number 등이 붙음.

### template_fields
각 Operator 클래스에 명시된, **Jinja 템플릿이 적용되는 인자 목록**.
`BashOperator.template_fields = ('bash_command', 'env', 'cwd')`.

### Trigger Rule
Task가 시작되는 조건. 기본은 `all_success` (모든 upstream success).
다른 옵션: `all_done` / `one_success` / `none_failed_min_one_success` 등.

### TriggerDagRunOperator
다른 DAG를 트리거하는 Operator. DAG 간 연결.

### Triggerer
Deferrable Operator (비동기 대기)를 처리하는 별도 컴포넌트. 본 학습 환경에는 미포함.

### `ts` / `ts_nodash`
`{{ ts }}` — logical_date의 ISO 8601 문자열. `ts_nodash`는 `:`,`-`,`+` 제거.

---

## U

### upstream / downstream
어떤 Task의 위쪽(상류) / 아래쪽(하류).
`a >> b`에서 a는 b의 upstream, b는 a의 downstream.

### upstream_failed
upstream Task가 failed라서 자동으로 실패 처리된 상태.

---

## V

### Variable
키-값 저장소. Admin → Variables. `{{ var.value.key }}` 또는 `Variable.get('key')`.

---

## W

### Webserver
Flask 기반의 UI / REST API 서버. 사용자가 보는 화면.
**DAG를 직접 실행하지 않음** (트리거만 하고 실제 실행은 Scheduler).

---

## X

### XCom (Cross-Communication)
Task 간 작은 값 전달 메커니즘. 메타DB에 저장.
**작은 메타데이터만** 권장 (DataFrame 등 큰 데이터 X).

---

## 자주 헷갈리는 용어 매트릭스

| 용어 A | 용어 B | 관계 |
|-------|-------|------|
| DAG | DAGRun | 정의 vs 1회 실행 |
| Task | TaskInstance | 정의 vs 1회 실행 |
| Operator | Task | 클래스 vs 인스턴스 |
| logical_date | 실제 실행 시각 | 논리 시점 vs 물리 시작 (보통 logical_date + 1 interval 후) |
| catchup | backfill | 자동 (DAG ON 시) vs 수동 (사용자 트리거) |
| Variable | params | 동적 (UI에서 변경) vs 정적 (DAG 정의 시) |
| Variable | XCom | 영구 / 전역 vs 1회 / DAGRun 한정 |
| dag_run.conf | params | 수동 트리거 시 입력 vs DAG 정의 시 기본값 |
| max_active_runs | max_active_tasks | DAGRun 수 vs Task 수 |
| Pool | priority_weight | 슬롯 vs 우선순위 |
| Sensor (poke) | Sensor (reschedule) | 슬롯 점유 vs 슬롯 양보 (양도) |
