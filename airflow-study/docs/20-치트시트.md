## SQL Where 절 패턴

```sql
-- 일일 파티션
WHERE event_date = '{{ ds }}'

-- 정확한 시간 구간 (정석)
WHERE ts >= '{{ data_interval_start }}'
  AND ts <  '{{ data_interval_end }}'

-- 어제 데이터
WHERE event_date = '{{ macros.ds_add(ds, -1) }}'

-- 7일 전 ~ 어제
WHERE event_date BETWEEN '{{ macros.ds_add(ds, -7) }}'
                     AND '{{ macros.ds_add(ds, -1) }}'
```

## DAG 정의 보일러플레이트

```python
from datetime import datetime
from airflow import DAG
from airflow.operators.bash import BashOperator

with DAG(
    dag_id="my_dag",
    description="설명",
    start_date=datetime(2026, 1, 1),     # 절대 datetime.now() 쓰지 말 것
    schedule="@daily",                    # 또는 "0 3 * * *"
    catchup=False,                        # 학습 환경 권장
    max_active_runs=1,                    # 백필 시 안전
    default_args={"retries": 1},
    tags=["learning"],
) as dag:
    t1 = BashOperator(task_id="t1", bash_command="echo {{ ds }}")
    t2 = BashOperator(task_id="t2", bash_command="echo done")
    t1 >> t2
```

## TaskFlow API (2.0+)

```python
from airflow.decorators import dag, task
from datetime import datetime

@dag(start_date=datetime(2026, 1, 1), schedule="@daily", catchup=False)
def my_pipeline():

    @task
    def extract():
        return 100

    @task
    def transform(value: int):
        return value * 2

    @task
    def load(value: int):
        print(value)

    load(transform(extract()))

my_pipeline()
```

## CLI — 자주 쓰는 명령

```bash
# 컨테이너 진입
docker compose exec airflow-scheduler bash

# DAG 목록 / 트리거 / 백필
airflow dags list
airflow dags list-import-errors                          # ★ 파싱 에러 확인
airflow dags trigger <DAG_ID>
airflow dags trigger -c '{"k":"v"}' <DAG_ID>
airflow dags pause <DAG_ID>
airflow dags unpause <DAG_ID>

# 백필
airflow dags backfill -s 2026-04-01 -e 2026-04-05 <DAG_ID>
airflow dags backfill -s ... -e ... --reset-dagruns -y <DAG_ID>
airflow dags backfill -s ... -e ... --rerun-failed-tasks <DAG_ID>
airflow dags backfill -s ... -e ... --dry-run <DAG_ID>

# Task 디버깅
airflow tasks list <DAG_ID> --tree
airflow tasks render <DAG_ID> <TASK_ID> <YYYY-MM-DD>     # Jinja 결과 미리보기
airflow tasks test <DAG_ID> <TASK_ID> <YYYY-MM-DD>       # 메타DB 안 거치고 단발 테스트
airflow tasks clear <DAG_ID> -s ... -e ... -y            # 상태 초기화

# 상태 조회
airflow dags list-runs -d <DAG_ID>
airflow dags state <DAG_ID> <ISO_DATETIME>

# Variable / Connection
airflow variables list / get / set <KEY> <VAL> / delete <KEY>
airflow connections list / get / add <ID> --conn-... / delete <ID>

# DAG 객체 직접 검증 (파일을 Python처럼 실행)
python /opt/airflow/dags/my_dag.py
```

## TaskInstance 상태 색상

| 색 | 상태 | 의미 |
|----|------|------|
| ⚪ 회색 | none / queued | 대기 |
| 🔵 라이트 블루 | scheduled | 큐 진입 직전 |
| 🟢 라이트 그린 | running | 실행 중 |
| 🟢 다크 그린 | success | 성공 |
| 🔴 빨강 | failed | 실패 (재시도 끝) |
| 🟠 오렌지 | up_for_retry | 재시도 예정 |
| 🟡 노랑 | up_for_reschedule | Sensor 양보 대기 |
| 🟣 보라 | upstream_failed | 상위 실패로 자동 실패 |
| 🌑 진회색 | skipped | 건너뜀 (분기/Short-circuit) |

## conf 활용 패턴

수동 트리거 시 다양한 입력 받기:

```python
def main(**context):
    conf = context["dag_run"].conf or {}
    region   = conf.get("region", "kr")          # 기본값 kr
    dry_run  = conf.get("dry_run", False)        # 기본값 False
    user_id  = conf.get("user_id")               # 필수면 None 체크
    if user_id is None:
        raise ValueError("user_id is required in conf")
```

UI에서 입력:

```json
{"region": "us", "dry_run": true, "user_id": 42}
```

CLI:

```bash
airflow dags trigger -c '{"region":"us"}' my_dag
```

## 자주 하는 실수 → 빠른 해결

| 실수 | 증상 | 해결 |
|------|------|------|
| `start_date=datetime.now()` | 매번 logical_date 바뀜 | 고정 datetime으로 |
| 모듈 최상위에서 무거운 import | 파싱 느림 | 함수 안으로 이동 |
| `bash_command="python {{ ds }}"` 인데 `task_id`에 `{{ }}` 시도 | 치환 안 됨 | `template_fields` 확인 |
| `catchup=True`로 두고 DAG ON | 과거 수개월치 한꺼번에 큐잉 | `catchup=False` + 명시적 백필 |
| BranchPythonOperator의 join | 한쪽 skipped라 join도 skipped | `trigger_rule=NONE_FAILED_MIN_ONE_SUCCESS` |
| `Variable.get` 모듈 최상위 | Scheduler가 매번 DB 호출 | Task 함수 안에서 호출 |
| timezone 혼동 | 시간 어긋남 | logical_date는 항상 UTC 저장 / UI 표시만 토글 |
